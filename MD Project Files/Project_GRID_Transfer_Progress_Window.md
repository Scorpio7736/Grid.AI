Before `grid -copyto` or `grid -transferto` confirmation, the preview now shows a rough duration range based on inventoried bytes and file count. It is explicitly approximate: destination hardware, small-file overhead, hashing and final verification affect actual time. No benchmark files are written to the destination before approval. The duplicate Continue prompt is removed; the existing confirmation remains authoritative.

After approval and the final save, a separate Windows progress window opens. It shows an estimated overall progress bar, current phase, file counts, elapsed time, estimated remaining copy time, destination and the seven most recent activity messages. Byte progress updates during large-file copying; hashing and validation identify what is being checked. The display continues timing while the original terminal performs synchronous checks. Remaining time is shown as estimating during final validation/cleanup instead of promising an unsupported precise finish time.

Copy progress stops at 85% until save/assets validation and publication finish. A move remains cleanup-pending until the destination's recorded cleanup status confirms success; it must not show completion merely because copying ended. Failures are distinct from success. If the host exits without a completion report, the viewer reports that outcome. Closing the viewer never cancels the transfer or grants it new authority. Keep removable media connected until completion.

The observer reads a bounded status snapshot written atomically in a unique local temporary directory. It runs as a separate built-in Windows PowerShell/WinForms process, so it does not keep the source GRID executable loaded during move cleanup. Transfer ownership, authorization, save timing, hash checks and source-retention rules remain in the original host. The new `Grid-TransferProgress.ps1` is copied into build/publish output and travels with the application. There are no new install dependencies. Redirected sessions or failed window initialization retain the existing text progress fallback. Status files are small diagnostic artifacts in the OS temporary directory, not saved world data.
